# ClassSight AI – Phase 5 Walkthrough: Backend & Data Platform

## Summary

ClassSight AI has been extended to **Phase 5: Backend & Data Platform**, transforming the computer vision and behavioral analysis pipeline (Phases 1-4) into a robust, multi-tenant academic intelligence platform.

Phase 5 decouples the AI pipeline from presentation and persistence, establishing a normalized PostgreSQL/SQLite relational database, Alembic schema migrations, an asynchronous FastAPI backend with JWT authentication, role-based access control (RBAC), and an automated ingestion service that maps Phase 3 behavior and Phase 4 engagement reports into persistent relational records.

## Phase 5.1: Backend Hardening & Semantic Data Integrity

Following Phase 5, Phase 5.1 was executed to resolve data integrity risks and enforce strict semantic verification:

### 1. Root Cause Resolution
- **0 Present & 0.0% Attendance Rate**: The Phase 5 E2E script had ingested a short 25.4s video report where all observations fell below `MIN_ATTENDANCE_DURATION = 30.0s`, legitimately assigning `UNCERTAIN` or `ABSENT`. The test asserted only HTTP 200 rather than validating semantic values.
- **Average Engagement `None`**: All students in the sample report had `engagement_level: "INSUFFICIENT_DATA"`. `get_lecture_summary` correctly filtered out un-scored students, leaving an empty set and yielding `None`.

### 2. Hardening Measures Implemented
1. **Attendance Uniqueness Constraint**: Added `UniqueConstraint("lecture_id", "student_id", name="uq_attendance_lecture_student")` to the `attendance` table.
2. **Alembic Migration**: Created and verified migration `2b3c4d5e6f7a_add_attendance_constraint_and_idempotency.py` supporting both SQLite (batch mode) and PostgreSQL.
3. **Idempotent Ingestion**: Added indexed `idempotency_key` column to `processing_sessions`. Ingestion computes a SHA-256 fingerprint from `lecture_id` and report data; duplicate ingestion returns `is_duplicate=True` without duplicating child records.
4. **Attendance Upsert**: Re-ingestion or updated report submission performs an in-place update of attendance rows rather than throwing duplicate key errors.
5. **Behavior-Only Attendance Derivation**: Ensured reports with only `per_student_events` correctly derive attendance for enrolled students.
6. **Attendance Rate Isolation**: Confined `present_count` in lecture summary strictly to enrolled classroom members, ensuring rates never exceed 100%.
7. **CSV Injection Protection**: Added `_sanitize_csv_cell` to neutralize spreadsheet formulas starting with `=`, `+`, `-`, `@`.
